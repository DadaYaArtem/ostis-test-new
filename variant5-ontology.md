# Минимальное наполнение онтологии для варианта 5

## 1. Классы и их ориентировочное наполнение
- `district` — районы города (центральный, кировский, ленинский и др.). Минимум: все районы, упомянутые во входных данных (для примера из методички — 8 штук, но в реальном наборе должно быть ≥ N из постановки).  
- `transport_route` — сущности маршрутов общественного транспорта. Количество совпадает с числом уникальных связей между районами (пример: 8 маршрутов).  
- `transport_type` — категориальные объекты для автобус/метро/трамвай (минимум 3). Возможное расширение: `bus`, `metro`, `tram`.  
- `transport_identifier` (опциональный класс) — объектные обозначения маршрутов (`№5`, `линия 1`, `№12`), если нужно хранить формальные номера.

## 2. Отношения
- `connects` (`district`, `district`, `transport_route`) — связывает два района конкретным маршрутом (неориентированное концептуально; храним как пара рёбер или через связку route→district).  
- `has_transport_type` (`transport_route`, `transport_type`) — тип транспорта для маршрута.  
- `has_identifier` (`transport_route`, `transport_identifier`) — номер маршрута.  
- `route_length` или `route_weight` — числовой атрибут (если учитываем расстояния/веса, по умолчанию можно оставить единичный).  
- `base_location` — отмечает стартовую/базовую точку (например, `Мира`), если требуется для агентов.

## 3. Шаблоны (SCs/SCn) и структуры
- `transport_network_structure` — база фактов: для каждого маршрута шаблон вида  
  ```
  route_X -> district_A;  
  route_X -> district_B;  
  route_X -> transport_type_bus;
  ```  
  где X — уникальный идентификатор.  
- `district_classification_template` — список районов (для перебора всех вершин).  
- `route_listing_template` — извлечение всех маршрутов, их типов и связанных районов.  
- `connectivity_query_template` — шаблон, по которому агент получает смежность (route → pair of districts).  
- `result_writing_template` — где агенты фиксируют выводы (`reachable_district`, `shortest_path_length`, `central_district`, `bridge_route`, `network_diameter_value`).

## 4. Примерное количество объектов
- Районы (`district`): N (минимум 8 по примеру, адаптируем под фактический список).  
- Маршруты (`transport_route`): равно числу линий (пример — 8).  
- Типы транспорта (`transport_type`): 3 базовых значения.  
- Идентификаторы (если выделены): по одному на маршрут.  
- Результирующие узлы (`analysis_result`, `central_district_marker` и т. п.) создаются агентами динамически.

## 5. Набор агентов
1. **GraphExtractionAgent** — читает `transport_route` и формирует внутренние структуры графа (списки смежности, веса).  
2. **ConnectivityAgent** — DFS/BFS по графу для проверки связности и выявления недоступных районов.  
3. **ShortestPathsAgent** — вычисляет кратчайшие пути между всеми парами (BFS для невзвешенного графа).  
4. **CentralityAgent** — используя матрицу расстояний, определяет центральный район (минимальный эксцентриситет).  
5. **BridgeDetectionAgent** — находит мостовые маршруты (алгоритм Тарьяна).  
6. **DiameterAgent** — вычисляет диаметр графа (максимум кратчайших расстояний).  
7. **ResultWriterAgent** (можно встроить в существующих) — записывает вычисленные показатели в SC-память согласно шаблонам.

Этого набора классов, отношений, шаблонов и агентов достаточно для выполнения требований варианта 5: построения графа, анализа связности, поиска кратчайших путей, определения центральности, мостов и диаметра.
